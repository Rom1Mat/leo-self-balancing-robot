# Léo — Self-Balancing ESP32-S3 Robot (LEGO figurine)

**Léo** is a two-wheeled inverted-pendulum robot that balances on its own, is driven from
your phone (real-time touch joystick over WiFi/WebSocket), animates its two arms, and can
run a short autonomous dance. A Bluetooth **Xbox One 1708** can also control it directly.
Brain: an **ESP32-S3**.

## ✨ Features
- **Self-balancing** on two wheels (500 Hz control loop on a dedicated ESP32 core).
- **Real-time control** from any phone/PC: a web page with a **touch joystick**
  (forward/back + turn), no app to install.
- **Direct Xbox control**: left stick driving, A/B for motors, Y for dynamic arm swing.
- **Exclusive Web / Xbox selection** prevents competing driving commands.
- **Two servo arms**: adjustable positions + preprogrammed gestures (wave, up, down).
- **Autonomous 32 s dance** with trajectory estimation (odometry without encoders).
- **Live tuning** from the browser: every control gain, live angle chart and diagnostics.

## 🧠 How it works (in short)
- An **MPU6050** (gyro + accelerometer) provides the tilt, fused with a complementary filter.
- A **PD-on-acceleration** controller computes the wheel acceleration needed to stay
  upright; an outer **PI speed loop** prevents drift and lets you drive by commanding a
  *speed* rather than a fixed lean angle.
- Motor steps are generated by **DDS** (a phase accumulator in a 40 kHz interrupt): the
  commanded speed is applied instantly, with no ramp or dead time — essential for balance.
- Web driving runs over **WebSocket**; settings use HTTP. Xbox uses a separate
  NimBLE task and keeps the HID state until release or detected BLE disconnection.

## 🔌 Wiring

| Signal | ESP32-S3 pin |
|--------|--------------|
| **Left** motor STEP / DIR | GPIO **2** / GPIO **41** |
| **Right** motor STEP / DIR | GPIO **42** / GPIO **1** |
| **EN** (both drivers, LOW = enabled) | GPIO **14** |
| MPU6050 **SDA / SCL** | GPIO **4** / GPIO **5** |
| **Left / right** arm servo | GPIO **15** / GPIO **16** |
| MPU6050 VCC / GND / AD0 | 3V3 / GND / GND |

**Power:** driver VMOT → 12 V (+ 100 µF per driver). ESP32 and servos at 5 V.
**A common ground is mandatory** between the motor supply, the ESP32 and the MPU.

**DRV8825 microstepping = 1/16** → on each driver: **M0 = GND, M1 = GND, M2 = 3V3**
(check your board's silkscreen; full table in the DRV8825 datasheet).

⚠️ Never plug/unplug a stepper motor while the driver is powered — it can destroy the DRV8825.

## ⚙️ Firmware

### Arduino libraries
- **Adafruit MPU6050** (+ **Adafruit Unified Sensor** as a dependency)
- **WebSockets** by *Markus Sattler (Links2004)*
- **NimBLE-Arduino 2.5.1** by *h2zero*.
- Everything else (WiFi, WebServer, timer, LEDC) ships with the ESP32 core.

### Install
1. Install **ESP32** board support in the Arduino IDE (Espressif boards manager).
2. Select your **ESP32-S3** board.
3. Open `self_balancing_robot/self_balancing_robot.ino`. Keep `XboxBle.h` beside it.
4. **Set your WiFi** at the top of the file:
   ```cpp
   const char* ssid     = "YOUR_WIFI";
   const char* password = "YOUR_PASSWORD";
   ```
5. Upload. Open the serial monitor (115200) to read the robot's IP address.
6. Open that IP in your phone's browser → remote control + settings. Select
   **Piloter avec le site** to drive from the page: Xbox is the default source.
7. For Xbox, update the 1708 controller to BLE firmware, pair once, then select
   **Piloter avec la manette**. See the [Xbox guide](INSTALLATION-XBOX.md).

Compilation verified with Arduino-ESP32 **3.3.11**, **ESP32S3 Dev Module** and
NimBLE-Arduino **2.5.1**. Public Wi-Fi values are placeholders. The web page is
embedded in the sketch; no separate HTML upload is required.

### Tuning
- Hold the robot by hand for the first runs: the provided gains are **starting points,
  to be refined on your own mechanics**.
- Capture your real **balance angle** with the dedicated button on the page.
- Tune **Kp / Kd (acceleration)**, then the **speed loop (Kp/Ki)**.
- If it vibrates at the balance point: lower the **motor current (DRV8825 Vref)** — it's
  the most common cause of low-speed resonance.

## 📱 Usage
- **Start motors**, then drive with the **joystick** (up = forward, left/right = turn).
- **Release** the joystick → automatic braking while balancing.
- **Arm** buttons: wave / up / down / rest, and the autonomous **dance**.
- Fully touch-based, built for phones (full screen; "Add to Home Screen" for an app-like icon).

### Xbox controls and dynamic arm swing

| Control | Action |
|---------|--------|
| A, with left stick centered | Start balancing |
| B | Cut motor output |
| Left stick up / down | Forward / reverse |
| Left stick left / right | Turn |
| D-pad up / down | Raise / lower the left arm |
| Right stick up / down | Raise / lower the right arm |
| Y | Toggle dynamic arm swing |

RT/LT are unused. A held command remains active without repeated HID reports.
Release clears motion; a detected BLE disconnection clears it and requires a
centered stick before resuming. Pairing keys survive normal restarts.

**Y** makes both hands follow the direction of travel, with a stronger initial
projection and a small alternating swing. Manual controls override their own
arm. Releasing the driving stick or disabling the mode returns the arms smoothly
toward 90°. The profile uses a 50° projection, 25° transient accent, 8° swing and
±60° target limit. Automatic speed is capped at **200°/s**, acceleration at
**1,000°/s²**, and manual arm speed at **140°/s**. The mode starts disabled and
is suspended with motors off, lost connection, Web control or dance.

### Current default settings

| Setting | Default | Adjustable maximum |
|---------|---------|--------------------|
| Wheel speed limit | 12,000 steps/s | 16,000 steps/s |
| Forward / reverse target | 4,800 steps/s | 8,000 steps/s |
| Turn differential | 2,500 steps/s | 4,000 steps/s |
| Balance acceleration limit | 200,000 steps/s² | 200,000 steps/s² |

Balance gains: **Kp = 18,000**, **Kd = 700**. Translation is additionally capped
at 60% of the wheel speed limit to leave room for balance corrections. These
values assume **1/16** microstepping, **90 mm** wheels and **160 mm** track.

## Development checks

Run from the repository root with Node.js:

```sh
node check_control.cjs
node check_remote_protocol.cjs
node check_xbox.cjs
```

Tests cover control calculations, web protocol, a simulated 60-second held Xbox
command, arm swing and disconnection handling. They translate selected C++
functions into JavaScript and do not validate the radio or physical robot.

Optional mobile browser checks:

```sh
npm install --no-save playwright
npx playwright install chromium
node check_remote_browser.cjs
```

Set `PLAYWRIGHT_BROWSER_PATH` to use an existing Chromium-based executable.
`telecommande.html` and `telecommande.js` mirror the page embedded in the sketch;
the protocol check verifies synchronization.

## 🛟 Safety
- The robot can fall / roll away: run tests in a clear space.
- Web driving has a **350 ms** command timeout. Xbox uses BLE link supervision
  (**500 ms requested**, negotiated value logged); motion is cleared on detected
  disconnection. This cannot detect a frozen controller application if BLE stays
  connected. Physical braking depends on the balance controller.
- The larger, faster arm swing still needs checking on the real robot; compilation
  and software tests do not confirm its physical stability.
